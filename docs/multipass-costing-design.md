# Multi-pass (per-colour) costing — design decisions and test results

Status: design closed 2026-10-06 (thirty-third update); build started 2026-10-09 on feat/multipass. Merged into docs/ARCHITECTURE.md §17 on 2026-10-09, which also records how this doc was reconciled with master 0.10.30 (§17.2); where the two disagree, ARCHITECTURE §17 wins. This file stays as the decision log. Companion doc: docs/column-view-presets-design.md (column toggles, button greying).
Repo: PrintJob (master only, no worktrees yet). Excel builds used for tests: 16.0.20430 (Windows); Excel for Mac 16.113.3 (Adam, roll-up test only).

## Settled decisions (Adam, 2026-10-04 to 06)
1. Option A style structure: a multi-pass job = one parent "Job" row + child "Pass" rows underneath, one per colour, in a collapsible row group (parent on top, Excel's +/- margin control on the parent).
2. Printers get: colour mode (`single pass` / `multi-pass`) and `Template cost` (start-up cost of one colour pass, e.g. RISO master). Single-pass printers behave exactly as today.
3. SUPERSEDED in part by decision 26 (Consumables sheet layout). Colours link to printers through the existing `Consumable type`: a type entry in `tblConsumables` (Settings sheet) is assigned to every printer of that kind, and each colour names that type. A multi-pass job's colour dropdown lists colours of its printer's type. Single-pass printers keep the type as a label and their own Cost per m2 (unchanged). (Confirmed with Adam 2026-10-06.)
4. New `Row Type` column (Job / Pass). Reports read parent (Job) rows only. Separate `Passes` count column (not a reused colour column) for multi-pass jobs (shown in reports; filter single vs multi-pass; sort by number of passes). No per-colour report for now. (Filter/sort detail: decision 32.)
5. Dedicated colour column (not the Printer column). Hidden in Reduced view for now; later managed by presets.
6. Dedicated `Set-up Cost` column, part of the existing cost-columns group (hidden/shown by the existing toggle). Leaves room for other processes with set-up costs.
6a. Set-up cost semantics (Adam 2026-10-06: "setup costs are part of the consumable cost but include it separately as part of the gross costs"). Recorded reading: `Consumable Cost` column = ink only; `Set-up Cost` its own column; set-up counts as a consumable cost for disregarding, but is its own term in Gross:
   - Pass row: Consumable Cost = ROUND(Area m2 x S_ConsRate); Set-up Cost = S_SetupCost (stamped from the printer's Template cost at pass creation).
   - Job row (multi-pass): Consumable Cost = sum of its passes; Set-up Cost = sum of its passes. Single-pass jobs: Set-up Cost 0/blank.
   - Gross = Paper + Consumable + Set-up. Chargeable = (Disregard Paper ? 0 : Paper) + (Disregard Consumable ? 0 : Consumable + Set-up). Disregarded = Gross - Chargeable.
   - Needs a Set-up column carried through `_Data`, Summary, Reports, Export/Import (schema bump). (Adam was told this reading and did not object; if he meant the Consumable Cost column itself to include set-up, this changes.)
7. Buttons above the table, visually separated from Add print job: Add pass, Remove pass (work on multi-pass job rows, also when a child row is selected), a per-job Toggle passes button (acts on the selected job, also when a child is selected), and a Toggle all passes button. Toggle all rule: if the groups are a mix of expanded/collapsed, first expand all so they match; if all expanded, collapse all; if all collapsed, expand all. Add print job when a pass row is selected must add the new job below that whole group. Excel's own margin +/- control stays too. (Button greying/self-disabling: see decision 22.)
8. Printer change on a job: blocked if the job has children. Single -> multi-pass allowed; multi-pass with no children -> single allowed. Deleting a job deletes the whole parent+children group (with confirmation). Deleting an earlier job shifts later rows up, so deletes must use whole-row delete (see tests) and re-assert group levels.
9. Colours may repeat within a job. Disregard Paper / Disregard Consumable are set on the parent only and apply to all passes (including set-up). Multi-pass is sheet stock only.
10. A multi-pass job with no passes is an invalid job (at least one colour required). Orphan children should never exist; if found: flag, remove, warn the workbook is probably broken.
11. Ink area per pass = whole page (parent's sheet area x Qty). Colour prices already assume typical coverage, same as existing per-printer consumable rates.
12. NO sorting and NO filtering on location sheets (rows stay in the order added, matching Job ID). The Reports sheet is the place for both and gets expanded filtering before this feature. That Reports work happens BEFORE this feature.
13. Development in one block on a worktree branch, after master is up to date. Modularising the VBA is a valued (possibly later) goal.
14. Column display presets are increasingly important to Adam: must cover single and multi-pass use cases; prefer independent toggles (like the cost-columns button) over a long list of presets. Design now agreed — see decision 22 and the companion doc.
15. Pass identity (agreed 2026-10-06): pass rows get NO Job ID of their own. Each carries its parent's Job ID in a Parent column plus a pass number (1, 2, 3...). No second ID counter. Import replaces a job's whole pass group as one block, so a job is never half-imported.
16. Roll-up (Adam, 2026-10-06, "go with B"): hidden helper columns. Pass rows compute own ink and set-up into hidden helper columns (H_Ink, H_Setup); the visible Consumable Cost and Set-up Cost on a Job row = SUMIFS of the helper columns over rows whose Parent = the job's ID; on a Pass row = its own helper value. Safe from circular references by construction. Verified formulas in RollUp-MacTest.xlsx (tblB). Costs two extra hidden columns.
17. Reports (Adam, 2026-10-06: "don't export additional colour pass details into a report. show the number of passes on a job and the setup costs"): Reports/Summary contain NO per-pass/colour detail rows; per job they show the number of passes and the set-up cost.
18. Workbook Export/Import (Adam, 2026-10-06: "include them for workbook exports - one table so as to limit the number of csv files"): the Export includes pass rows so Import can rebuild them. ONE table / one CSV: pass rows are extra rows in the same jobs file, distinguished by Row Type, with Parent job ID and Pass number (per decision 15). Import regroups by Parent ID and replaces a job's pass group as one block.
19. `_Data` (Adam, 2026-10-06, "yes option a"): holds Job rows only. Pass rows are not consolidated into `_Data`, so Reports/Summary formulas are unchanged apart from the new Passes and Set-up columns. `_Data` therefore needs Passes and Set-up Cost columns (Job rows carry the rolled-up values).
20. Backward compatibility (Adam, 2026-10-06, "yes they should be importable"): exports from the current schema (1.3, no Row Type/Parent/Pass/Set-up columns) must still import into the new version. Missing columns default: Row Type = Job, Passes = 0/blank, Set-up = 0, single-pass. (Defaults are my reading of "importable"; Adam has not specified them.)
21. Pass rows in the shared CSV (Adam, 2026-10-06, "option A"): a pass row carries only Row Type, Parent job ID, Pass number, colour, ink (consumable) cost and set-up cost; all other job fields (student, technician, date, paper, quantity, etc.) are blank. Import takes job details from the parent row only.
22. Column toggles and buttons (Adam, 2026-10-06; full detail in docs/column-view-presets-design.md): a separate group toggle for the multi-pass columns (colour + Passes) alongside the cost toggle; Set-up Cost stays with the cost toggle only; toggle and pass buttons appear on ALL location sheets, shaded lighter when no multi-pass printer exists; Add pass / Remove pass grey out unless a multi-pass job or pass row is selected, and clicking a greyed button shows a short message; the All/Reduced/Minimal drop-down stays as a layered "convenience" declutterer with the toggles acting on top. "All" shows everything EXCEPT groups toggled off (Adam, 2026-10-06, option A; see companion doc decision 8).
23. Price changes (Adam, 2026-10-06, "keep the stamped rate"): a pass row's ink rate (S_ConsRate) and set-up cost (S_SetupCost) are stamped when the pass is created and are NOT changed by later edits to the Consumables sheet or the printer's Template cost, matching today's snapshot rule for job rows.
24. Pass numbering (Adam, 2026-10-06, "auto renumber"): when a pass is removed, the remaining passes of that job are automatically renumbered 1, 2, 3... so numbers never have gaps. (Check should still flag a pass row whose number is out of sequence, as a sign of manual tampering — my addition, not discussed.)
25. Re-stamp prices (Adam, 2026-10-06, "yes absolutely"): the Settings "Re-stamp prices" action also re-stamps pass rows (ink rate from the current colour cost per m2, set-up cost from the printer's current Template cost), so mistakes in price entry can be corrected as for job rows.
26. Consumables sheet layout (Adam, 2026-10-06: "use the consumable types table on the settings sheet to define the types as now (including a new 'risograph' type), but actual colours and prices should be defined in a new 'Consumables' sheet, functionally similar to the existing printers and papers sheets. it should have an ID column so the names can be modified (eg spelling) without breaking existing references"):
   - `tblConsumables` on Settings (Consumable type, Active) stays as the list of TYPES; a new type for risograph is added (exact label e.g. "Risograph" — capitalisation not confirmed).
   - New sheet "Consumables" with its own table, functionally like the Printers/Papers sheets (add/remove row buttons, deactivate-not-delete, locked ID column).
   - It has an ID column following the existing catalogue scheme: `<SITE>-TCH-0001`, `<SITE>-PRN-0001`, `<SITE>-STK-0001` are allocated by modCatalog.NextCatalogId with a persisted high-water counter per table in tblSettings (e.g. PRINTER_ID_HWM); the colours table would follow it (e.g. `<SITE>-CLR-0001`, new counter) — the ID format is my proposal, not yet confirmed.
26a. REFINED by Adam later the same day ("ok keep it the same as printers and papers for now"), after I showed that today's catalogue IDs are NOT the lookup key (StampRow looks up Prn(name)/Stock(name); IDs serve Backup/Restore matching and are copied onto job rows as S_PrinterID/S_StockID/S_TechID): colours work exactly like printers and papers — ID column present, lookups by NAME, `S_ColourID` snapshot on pass rows (by analogy with S_PrinterID; not discussed). Known limitation, accepted for now: renaming a colour leaves existing pass rows unable to find it by name (Re-stamp prices would blank their rate — same as printers/papers today). Adam asked for an item on the Proof Sheet to revisit IDs vs names for printers, papers, technicians and colours in one go: ADDED 2026-10-06 to the PrintJob Proof Sheet punch list ("Catalogue references: IDs vs names (revisit all at once)").
27. Consumables table columns (Adam, 2026-10-06, "no other columns for now. a visual representation of the colour might be nice in the future"): exactly ID, Consumable type, Colour, Cost per m2, Active — no notes/supplier/product-code columns. A colour swatch/visual representation is a possible FUTURE addition (not in scope; keep the table easy to extend).
28. Column placement (Adam, 2026-10-06, "yes i agree"): in the Reports results table, Summary and (by extension) Export column order, `Passes` goes immediately after the Printer column and `Set-up Cost` immediately after Consumable Cost, keeping the cost columns together.
29. Schema version (Adam, 2026-10-06, "yes that's fine"): bump SCHEMA_VER 1.3 -> 1.4 (minor, since 1.3 exports stay importable per decision 20). Make sure no parallel branch takes 1.4.
30. Check rules for colours (Adam, 2026-10-06: "for blank then yes flag it, but we should allow imports from workbooks with different colours defined, so a properly-formed pass row should import even if a colour is not available here. colours added in-sheet should of course be available in that sheet. do flag a mismatched consumable type"). Recorded reading:
   - A pass row with a BLANK colour is flagged by Check.
   - Import accepts a well-formed pass row whose colour is not defined in this workbook's Consumables sheet (carried as plain text, as imported printer/paper/technician names are today — ARCHITECTURE §10.5: Import never reconciles catalogues). Such a row is NOT flagged merely for being unknown here. Colours added on a workbook's own Consumables sheet are available in that workbook.
   - A pass row whose colour IS found but belongs to a consumable type different from the job's printer's type is flagged. (When the colour is unknown here the type cannot be checked. Adam, 2026-10-06: "you can give a warning so the user is aware, but still let it through. maybe add a note to the affected row?" — so such a row IS imported and kept, with a warning and a note on the row saying the colour is not defined here and its type could not be checked. Exact mechanism: see open question.)
31. Unknown-colour pass rows and Re-stamp (Adam, 2026-10-06, "leave alone"): "Re-stamp prices" leaves a pass row whose colour it cannot find in this workbook untouched (keeps its stamped ink rate and set-up cost; does not blank them). The imported ink cost and set-up cost from the file are kept and count in totals (my framing of the question; Adam did not object). Note this differs from today's behaviour for a printer/paper whose name can't be found (StampRow writes Empty for the rate) — the pass-row path must handle "not found" explicitly.
   - Adam's follow-up (2026-10-06): "this is an inconsistency so I'd like to revisit after this upgrade" — i.e. the difference between pass rows (leave alone) and job rows (blank when the printer/paper isn't found) should be revisited AFTER this upgrade is done. ADDED 2026-10-06 to the PrintJob Proof Sheet punch list (Adam: "yes please"), as its own item next to the catalogue IDs-vs-names item.
32. Reports filter and sort (Adam, 2026-10-06: "yes to filters and sorting options, though other filters treat a blank cell as 'all' so be consistent"): the Reports sheet gets a new filter for pass type (single pass / multi-pass) and "Passes" as a sort choice (decision 4). A BLANK filter cell means 'all', like the existing filters (Paid, Paper type etc.). Dropdown wording to follow the existing filters' style (e.g. values "Single pass", "Multi-pass"; exact labels not yet set). Placement within the filter block not yet decided.

Pass rows travel with the jobs CSV (decision 18).
35. Unknown-colour warning (Adam, 2026-10-06, "a milder warning yes", "separate notice"; refines decision 30): a pass row whose colour is not defined in this workbook is imported and kept, and counts normally in totals. It is shown through the existing Status column and hover note (read from modInit: Status = "OK" or a joined issue list from hidden H_Issues; real problems are filled orange by conditional formatting, message in a hover note via RefreshStatusNotes) but at a MILDER warning level: its own lighter fill (e.g. yellow; exact colour not set) and a note such as "Colour not defined in this workbook; type not checked" (wording not set). Residual unchecked point: whether the fresh template ships seeded printer rows that a restore would match by ID.

## Test results (throwaway workbooks in %TEMP%, deleted afterwards; project files untouched)
- Row groups inside an Excel table work; collapse/expand works from code, including on a sheet protected with UserInterfaceOnly. `EnableOutlining` is NOT persisted across save/reopen (reads False after reopen) — already re-applied on open by the existing protection code. Docs: EnableOutlining = "True if outlining symbols are enabled when user-interface-only protection is turned on" (learn.microsoft.com/office/vba/api/excel.worksheet.enableoutlining). Real user click on +/- while protected: not tested.
- `Outline.SummaryRow` (xlSummaryAbove = 0 puts the +/- on the parent row) can NOT be changed once the sheet has a table (error). It CAN be set before a table exists, and then survives table creation, grouping, save/reopen and sheet duplication (Copy). The existing template has `<sheetPr codeName="Sheet10"/>` on the location sheet; patching it to `<sheetPr codeName="Sheet10"><outlinePr summaryBelow="0"/></sheetPr>` in a temp copy opened cleanly with SummaryRow=0 and the table intact. So: bake summaryBelow="0" into PrintCosts.xlsx (XML patch, binary file, one-off).
- VISUAL CHECK (screenshots of a visible Excel, 2026-10-06): with summary-above, the [-] control appears on each Job row that has passes (none on a job without passes). Hiding only one job's pass rows directly (`Rows.Hidden = True`) flips just that job's control to [+] and leaves the others as [-]. So a per-job toggle can simply hide/unhide that job's pass rows. (`Range.ShowDetail` could not be set on a table sheet — use Hidden.)
- Outline levels belong to the sheet ROW, not the data. `ListRows.Add` / `ListRow.Delete` (cell-shifting) leave levels where they were, so groups become misaligned. Whole-row `Range.EntireRow.Insert` / `.Delete` keep levels aligned with the data and the table grows/shrinks. A row inserted this way inherits the row above's level and is visible, so code must set level/hidden explicitly.
- A rebuild routine (set every row in/under the table to level 1, unhide, then set level 2 + hidden for each Pass run from the Row Type column, preserving per-job collapsed state) fixes any misalignment: 2000 rows / 333 groups ~0.8 s; collapse-all 18 ms; one EntireRow.Insert 14 ms. Usable as repair and for Check workbook. (`Range.ClearOutline` failed from PowerShell; setting `OutlineLevel = 1` works.)
- Filtering vs groups: with groups collapsed and a filter on, expanding re-shows child rows the filter excluded; clearing the filter (ShowAllData) expands every group. Sorting: levels do not travel with data. Both are disabled on location sheets by decision 12.
- Validation: a new table row inherits the data validation of the row above, so validation must be rebound after each insert (existing BindColumns pattern).
- Roll-up (Windows, 16.0.20430): same-column `=IF([@Type]="Job",SUMIFS([Cons],[Parent],[@Job]),[@Own])` raised no circular reference and updated correctly; a positive control (`=SUM(A1:A3)` in A3) was detected, so detection works. Helper-column variant also works. Same-column reliance is an undocumented engine behaviour.
- Roll-up on Mac (Adam, 2026-10-06, Excel for Mac 16.113.3, RollUp-MacTest.xlsx): both variants (A same-column, B helper column) ALL PASS on the Check sheet; no circular reference warnings seen. +/- placement on Mac not reported.
- Forms buttons (Windows): `Enabled=False` settable on a protected sheet but not visibly greyed; caption font colour greys visibly but needs the sheet unprotected. Detail in the companion doc.
- Sheet protection (docs): AllowSorting needs every cell in the sort range unlocked; AllowFiltering lets users change filter criteria on an existing autofilter; AllowInsertingRows/AllowDeletingRows default False. Source: learn.microsoft.com/office/vba/api/excel.worksheet.protect.
- Not verified: real UI clicks on +/- while protected.
